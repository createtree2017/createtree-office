## 1. 기존 문제점

### 1.1 PowerShell 5.1의 한계

이 프로젝트는 Windows 환경에서 개발되며, VS Code 및 Antigravity(AI 코딩 도구)의 **기본 터미널이 PowerShell 5.1**로 설정되어 있었습니다. PowerShell 5.1은 아래와 같은 제약이 있어 개발 생산성을 저하시켰습니다:

| 문제 | 증상 | 발생 빈도 |
|------|------|----------|
| `&&` 체이닝 불가 | `git add -A && git commit -m "..."` 실행 시 파서 에러 (`InvalidEndOfLine`) | **매우 높음** |
| 한글 커밋 메시지 불가 | `git commit -m "한글메시지"` 실행 시 인코딩 깨짐 | 높음 |
| `||` 체이닝 불가 | `cmd1 || cmd2` 실행 불가 | 보통 |
| `export` 미지원 | `export NODE_ENV=production` 대신 `$env:NODE_ENV="production"` 사용 필요 | 보통 |
| Linux 문법 비호환 | 대부분의 npm 스크립트, 가이드, Stack Overflow 답변이 Bash 기준 | 지속적 |

### 1.2 실제 발생한 문제 예시

```powershell
# ❌ PowerShell 5.1에서 에러 발생
git add -A && git commit -m "feat: add caching"
# 에러: '&&' 토큰은 이 버전에서 올바른 문 구분 기호가 아닙니다.

# ❌ 한글 커밋 메시지 깨짐
git commit -m "기능: 캐싱 추가"
# 에러: InvalidEndOfLine

# ⚠️ 우회 방법: 명령어를 하나씩 분리 실행 (비효율적)
git add -A        # 1번째 실행
git commit -m "feat: add caching"   # 2번째 실행
git push origin develop             # 3번째 실행
```

### 1.3 왜 PowerShell 7로 업그레이드가 아닌 Git Bash인가?

| 비교 항목 | PowerShell 7 | Git Bash |
|----------|-------------|----------|
| `&&` 지원 | ✅ | ✅ |
| Linux 문법 호환 | ⚠️ 부분적 | ✅ 완벽 |
| 웹 개발 생태계 호환 | ⚠️ PS 문법 별도 | ✅ npm/node 네이티브 |
| 추가 설치 필요 | ✅ 별도 설치 | ❌ Git 설치 시 자동 포함 |
| 전 세계 개발자 사용률 | ★★★☆☆ | ★★★★★ |
| `export`, `source` 등 | ❌ 미지원 | ✅ 지원 |

## 2. 해결 방법: Git Bash로 기본 터미널 변경

### 2.1 사전 조건: Git Bash 설치 확인

#### 확인 방법

Windows 탐색기에서 아래 경로에 `bash.exe` 파일이 있는지 확인:

```
C:\Program Files\Git\bin\bash.exe
```

또는 PowerShell에서:

```powershell
Test-Path "C:\Program Files\Git\bin\bash.exe"
# True  → 설치됨 (2.2로 이동)
# False → 미설치 (2.1.1 설치 과정 진행)
```

#### 2.1.1 Git Bash 미설치 시 — Git for Windows 설치

1. **다운로드**: https://git-scm.com/download/win 접속
2. **"64-bit Git for Windows Setup"** 클릭하여 설치 파일 다운로드
3. **설치 진행** (대부분 기본값 유지, 아래 항목만 확인):

| 설치 단계 | 권장 설정 |
|----------|----------|
| Select Components | ✅ `Git Bash Here` 체크 확인 |
| Choosing the default editor | 원하는 에디터 선택 (VS Code 권장) |
| Adjusting your PATH environment | **"Git from the command line and also from 3rd-party software"** 선택 |
| Choosing HTTPS transport | Use the OpenSSL library |
| Configuring the line ending | **Checkout Windows-style, commit Unix-style** |
| Configuring the terminal | **Use MinTTY** |

4. 설치 완료 후, `C:\Program Files\Git\bin\bash.exe` 존재 확인

---

### 2.2 VS Code 기본 터미널을 Git Bash로 변경

#### 방법 A: 명령 팔레트 (권장, 가장 빠름)

1. VS Code 열기
2. `Ctrl + Shift + P` → 명령 팔레트 열기
3. **`Terminal: Select Default Profile`** 검색 → 클릭
4. 목록에서 **`Git Bash`** 선택
5. **기존 터미널 탭 모두 닫기** (중요! 기존 PS 터미널은 변경 안 됨)
6. `Ctrl + ~` 로 새 터미널 열기 → Git Bash 확인

#### 방법 B: settings.json 직접 수정

VS Code에서 `Ctrl + Shift + P` → `Preferences: Open User Settings (JSON)` → 아래 추가:

```json
{
    "terminal.integrated.defaultProfile.windows": "Git Bash"
}
```

#### 변경 확인 방법

새 터미널을 열었을 때 프롬프트가 아래와 같으면 성공:

```bash
# ✅ Git Bash (성공)
사용자@PC이름 MINGW64 ~/Desktop/createAI/createtree_office (develop)
$

# ❌ PowerShell (아직 변경 안 됨)
PS C:\Users\TOP\Desktop\createAI\createtree_office>
```

추가로 아래 명령어로 검증:

```bash
echo $BASH_VERSION && echo "Git Bash 정상 동작!"
# 출력: 5.2.37(1)-release
# 출력: Git Bash 정상 동작!
```

---

### 2.3 Antigravity (AI 코딩 도구) 터미널 변경

Antigravity는 VS Code의 터미널 설정을 따르므로, **VS Code 설정만 변경하면 자동으로 적용됩니다.** 별도 설정 불필요.

검증 방법: AI에게 `echo $BASH_VERSION` 실행을 요청하고, 버전이 출력되면 정상.

## 3. 변경 후 달라지는 점

### 3.1 명령어 변경 사항

| 작업 | 변경 전 (PowerShell) | 변경 후 (Git Bash) |
|------|---------------------|-------------------|
| 명령어 체이닝 | 각각 별도 실행 | `cmd1 && cmd2 && cmd3` |
| git 커밋 | 영문 단문만 가능 | 한글 포함 가능 (영문 권장은 유지) |
| 환경변수 설정 | `$env:VAR="value"` | `export VAR=value` |
| 경로 구분자 | `\` (백슬래시) | `/` (슬래시, 백슬래시도 가능) |
| 파일 내용 보기 | `Get-Content file` | `cat file` |
| 파일 찾기 | `Get-ChildItem -Recurse` | `find . -name "*.ts"` |

### 3.2 주의사항

1. **기존 PowerShell 터미널은 자동 변경 안 됨** — 반드시 닫고 새 터미널 열기
2. **Windows 경로도 여전히 사용 가능** — `cd /c/Users/TOP/Desktop/` 또는 `cd "C:\Users\TOP\Desktop\"` 모두 가능
3. **npm, node, npx 등은 동일하게 동작** — 차이 없음
4. **`.bat` 파일 직접 실행은 제한적** — 필요시 `cmd //c script.bat` 으로 실행

## 4. GEMINI.md 업데이트 필요 사항

기존 GEMINI.md의 `⚠️ PowerShell 터미널 규칙` 섹션은 Git Bash 전환으로 인해 대부분 불필요해졌습니다.  
단, 두 환경(사무실/집) 모두 Git Bash로 전환 완료된 후에 업데이트하는 것을 권장합니다.

### 유지할 규칙
- git commit 메시지는 **영문 단문** 유지 (관례상 권장)
- 여러 명령어는 `&&`로 체이닝 가능 (제한 해제)

### 제거 가능한 규칙
- ~~`&&` 미지원 → 명령어 분리 실행~~ (해결됨)
- ~~한글 커밋 메시지 금지~~ (기술적으로는 해결됨, 단 영문 관례 유지 권장)

## 5. 다른 환경(집/사무실) 적용 체크리스트

새 환경에서 이 설정을 적용할 때 아래 체크리스트를 따릅니다:

- [ ] Git for Windows 설치 확인 (`C:\Program Files\Git\bin\bash.exe` 존재 여부)
- [ ] 미설치 시 https://git-scm.com/download/win 에서 설치
- [ ] VS Code 열기 → `Ctrl + Shift + P` → `Terminal: Select Default Profile` → `Git Bash` 선택
- [ ] 기존 터미널 닫기 → 새 터미널(`Ctrl + ~`) 열기
- [ ] `echo $BASH_VERSION && echo "OK"` 실행하여 정상 동작 확인
- [ ] `npm run dev` 등 프로젝트 명령어 정상 동작 확인
