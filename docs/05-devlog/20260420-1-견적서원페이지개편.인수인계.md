# 인수인계: 견적서 작성 One-Page 통합 UI 개편

## 1. 작업 개요
- **날짜**: 2026-04-20
- **담당**: AI Agent
- **작업명**: 견적서 작성 화면의 레거시 위자드 UI 제거 및 엑셀(One-Page) 스타일의 통합 테이블 UI 도입

## 2. 변경 파일 목록
1. `server/src/db/schema.ts` (수정)
   - `quotationItems` 테이블에 `remark`(비고), `isCustom`(커스텀항목여부) 컬럼 추가.
2. `server/scripts/add-columns.ts` (신규)
   - DB 테이블 직접 조작을 통한 `remark`, `is_custom` 컬럼 추가 마이그레이션 스크립트 작성 및 실행.
3. `server/src/routes/quotations.ts` (수정)
   - POST / PUT API에서 프론트엔드가 전송하는 `remark`, `isCustom` 필드를 DB에 저장하도록 로직 업데이트.
4. `docs/02-design/features/1-20260420-견적서원페이지개편.design.md` (신규)
   - 원페이지 개편 상세 설계 문서.
5. `client/src/pages/QuotationsPage.tsx` (전면 수정)
   - 4단계 위자드 로직 걷어내고, `rows` 배열 하나로 관리되는 단일 테이블 UI로 660줄 재작성.

## 3. 핵심 변경 내용
### 3.1. 위자드(Wizard) UI ➡️ One-Page Table UI
- 사용자가 여러 화면을 넘어갈 필요 없이, 거래처와 계약 기간을 선택한 뒤 하나의 표(Table)에서 모든 견적 항목을 입력할 수 있도록 변경했습니다.
- **데이터 흐름의 단순화**: 
  - 복잡한 Map 객체(`selectedServices`) 대신, 테이블의 각 줄(Row)을 의미하는 `QuotationRow` 객체 배열 하나로 모든 상태를 통제합니다.

### 3.2. 직접 입력 및 할인 기능 통합
- 서비스 선택 드롭다운 하단에 **"+ 직접 입력"**과 **"- 할인 적용"** 메뉴를 기본 탑재했습니다.
- 할인을 별도의 로직으로 계산하지 않고, 금액 칸에 마이너스(-) 숫자를 입력하는 직관적인 형태로 변경하여 계산 로직(`reduce`)을 극도로 단순화했습니다.

### 3.3. DB 스키마 안전 마이그레이션
- Drizzle `push` 시 타인의 미적용 데이터(`supporter_applicants` 등)가 삭제되는 것을 방지하기 위해, `postgres` 스크립트(`add-columns.ts`)를 직접 작성하여 필요한 2개의 컬럼만 빠르고 안전하게 `ALTER TABLE` 했습니다.
