# 시장조사 목록 성능 개선 인수인계

## 작업 배경

- 시장조사 결과가 5천 건 이상 누적되면서 페이지 진입 시 전체 목록을 한 번에 내려받고 렌더링해 브라우저가 순간 정지하는 문제가 있었다.
- 첫 화면에서 전체 원본이 아니라 영업 가능성이 높은 산부인과 검증 후보를 우선 표시하도록 변경했다.
- 전체 시장조사는 실행하지 않았다.

## 변경 내용

- `server/src/routes/marketResearch.ts`
  - `/api/market-research/items`에 페이지네이션 메타를 추가했다.
    - 기본 `pageSize=50`
    - 최대 `pageSize=200`
    - 응답: `{ success, data, meta }`
  - 목록 기본 view를 `verified_obgyn`으로 변경했다.
    - 네이버 카테고리 `병원,의원>산부인과`
    - 기관명 예외 키워드 매칭
    - HIRA 상세조사 후보
  - `view=all`일 때만 전체 원본을 조회하도록 했다.
  - `view=delivery_candidates`, `view=detail_candidates` 필터를 추가했다.
  - `/api/market-research/summary`를 추가해 요약 카드 수치를 목록 payload와 분리했다.
  - `/api/market-research/items/ids`를 추가해 현재 view/filter 조건에 맞는 전체 항목 ID만 조회할 수 있게 했다.
  - `/api/market-research/items/select-batch`를 추가해 선택된 시장조사 항목을 영업선택업체로 일괄 저장할 수 있게 했다.
  - 엑셀 다운로드는 페이지네이션 없이 현재 view/filter 전체를 export하도록 유지했다.

- `client/src/hooks/useMarketResearch.ts`
  - 시장조사 필터에 `view`, `page`, `pageSize`를 추가했다.
  - 목록 hook 응답을 `{ items, meta }` 형태로 처리하도록 변경했다.
  - `useMarketResearchSummary` hook을 추가했다.
  - 현재 view/filter 전체선택용 `fetchMarketResearchItemIds`를 추가했다.
  - 선택 항목을 영업관리로 일괄 저장하는 `useBatchSelectMarketResearchItems` hook을 추가했다.
  - 실행/수정/영업선택/영업선택해제 후 목록과 요약이 함께 갱신되도록 invalidation을 보강했다.

- `client/src/pages/MarketResearchPage.tsx`
  - 기본 화면을 `분만산부인과` 필터로 설정했다.
  - 이후 중복되는 보기/업종 필터를 하나의 1차 필터로 정리했다.
    - `분만산부인과`: 분만 후보 조건
    - `일반산부인과`: 일반 산부인과 업종
    - `산후조리원`: 산후조리원 업종
    - `상세조사후보`: HIRA 상세조사 대상
    - `전체원본`: 전체 원본 데이터
  - 목록은 페이지당 50건만 렌더링한다.
  - 하단 페이지네이션을 추가했다.
  - 요약 카드는 서버 summary API 기준으로 표시한다.
  - 목록 카드 상단에 `전체선택`, `선택해제`, `선택업체 저장`, `영업관리로 이동` 버튼을 추가했다.
  - 페이지 상단 액션은 `엑셀 다운로드`, `시장조사 실행`만 남겼다.
  - 연락처 영역에 `네이버플레이스` 링크를 별도로 표시한다. 네이버 `link`가 없으면 자동 검색 URL을 만들지 않고 `플레이스 없음`으로 표시한다.
  - 편집 모달에 `네이버 플레이스 URL` 수동 입력 필드를 추가했다.
  - `홈페이지`와 `네이버플레이스`를 분리해 네이버 지역검색 `link`가 홈페이지로 섞이지 않게 했다.
  - `view=all`이 쿼리 생성 단계에서 누락되어 `전체원본`, `일반산부인과`, `산후조리원`이 0건으로 보이던 문제를 수정했다.
    - 원인: 공통 `toQuery`가 값이 `all`인 파라미터를 모두 제거했고, 서버는 `view`가 없으면 기본 `verified_obgyn`으로 처리했다.
    - 수정: `view=all`은 명시적으로 서버에 전달하도록 예외 처리했다.
  - 로컬 DB 기준 원본 데이터는 5,307건이며, 산후조리원은 1,014건 저장되어 있음을 확인했다.
  - Google Drive 시장조사 폴더 설정은 존재하며, 최신 산후조리원 CSV `건강_산후조리업_전국파일.csv` 조회를 확인했다.
  - 테이블 헤더의 선택 칸을 현재 페이지 전체선택/해제 토글로 변경했다.
  - 전체 원본은 명시적으로 선택했을 때만 조회한다는 안내를 추가했다.

- `.agents/skills/createtree-office-ops/SKILL.md`
  - 시장조사 결과 화면의 기본 후보 조회/전체 원본 선택 조회 규칙을 반영했다.

## 검증 결과

- `npm run lint --prefix client`: 통과
- `npm run build --prefix client`: 통과
- `npm run build --prefix server`: 통과
- `npm run skills:check`: 통과
- 로컬 브라우저 렌더링 확인은 Playwright 브라우저 바이너리 미설치로 실행하지 못했다.

## 운영 참고

- 이번 변경은 화면 조회 성능 개선이며 DB 스키마 변경은 없다.
- 서버는 현재 필터링 후 페이지 단위 응답을 내려보내므로 브라우저 렌더링과 네트워크 payload가 크게 줄어든다.
- 향후 데이터가 수만 건 이상으로 늘어나면 JSONB view 조건까지 DB where/index로 밀어 넣는 2차 최적화가 필요하다.
