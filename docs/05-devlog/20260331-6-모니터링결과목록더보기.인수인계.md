## 목적
- 모니터링 페이지의 '결과 목록' 탭에서 300개가 넘는 데이터를 한 번에 화면에 렌더링할 때 발생하는 심각한 UI 버벅임(DOM 병목 현상)을 해결하기 위함.

## 변경 파일 목록
- `client/src/pages/MonitoringPage.tsx`: 더보기 기반 페이지네이션 렌더링 로직 추가.

## 핵심 변경 내용
- `visibleResultCount` 상태를 컴포넌트 최상단에 추가 (기본값 30).
- `filteredResults.map(...)` 루프를 `filteredResults.slice(0, visibleResultCount).map(...)`으로 변경하여 최초 화면 진입 시 최대 30개의 카드 엘리먼트만 그리도록 로직 수정.
- 리스트 하단에 전체 개수와 함께 `[30개 더보기]` 버튼을 노출하고, 클릭 시 30개씩 추가 로드 되도록 이벤트 바인딩.
- 거래처 필터를 변경하거나 탭을 이탈했다 다시 돌아왔을 때, `visibleResultCount`를 항상 초기값인 30으로 즉시 초기화하는 `useEffect` 연동.

## 작업 완료 확인
- 결과 목록 및 거래처별 목록 페이지 접근 시 지연 없이 매우 즉각적으로 로딩됨 (메모리 로딩 최적화).
- "전체 선택" 체크박스의 카운팅 및 로직은 기존 원본 배열(`filteredResults`) 기반으로 동작하도록 분리되어 있으므로 다중 삭제 기능 등은 여전히 모두 완벽히 동작합니다.
