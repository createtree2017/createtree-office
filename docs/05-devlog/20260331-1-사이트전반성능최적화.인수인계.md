# 20260331-1-사이트전반성능최적화.인수인계

## 1. 개요
* **목적**: CreateTree Office 플랫폼 전반적인 로딩 지연 및 네트워크 병목 현상 해결 (N+1 쿼리 최적화, 불필요한 전체 데이터 조회 제거, 프론트엔드 무한 루프 등)
* **작업 요약**: 
  - 모니터링 페이지: 결과 API 응답 데이터 경량화 (`posts` 등 대용량 데이터 목록에서 제거) 및 프론트엔드 useEffect 조건문 오류로 인한 불필요한 자동 새로고침(polling) 무한 루프 문제 수정.
  - 견적서 페이지: 라우팅 시 전체 목록을 우선 조회한 후 단일 건으로 넘어가서 발생하던 렌더링 지연(깜빡임) 문제 해결.
  - 견적서/관리자 N+1 쿼리: 리스트 렌더링시 발생 가능한 수많은 N+1 쿼리 문제를 JOIN 및 일괄 데이터(`all-approved-services`) api 호출로 기존에 최적화 반영 완료된 것을 확인함.
  
## 2. 변경 파일 목록
* `client/src/pages/MonitoringPage.tsx`
  - 대용량 데이터를 한꺼번에 불러오는 방식 대신, `latestResultDetail` 상태를 새로 구성하여 대시보드의 '최근 분석 결과'에만 단일 상세 fetch.
  - `useEffect`의 의존성 배열에서 `results` 전체를 참조하던 부분을 분리하여 `hasRunning`이라는 boolean 참조 상태로 변경, 네트워크 API 무한 풀링(Polling) 루프 동작 방지.
  - 결과 탭 렌더링과 통계 정보를 표시할 때 기존의 API 모델 구조 (`overall_sentiment`)에 맞물려 표기되도록 누락된 구문 일괄 수정.
* `server/src/services/monitoring/monitoringService.ts`
  - 쿼리 `getResults()` 로직 최적화: 모니터링 전체 목록 쿼리 반환 시 대용량 JSON 컬럼인 `posts`, `statistics`를 생략하고 필수 요약수치(`postCount`, `overallSentiment`)를 내장 쿼리 문법으로 치환하여, API 트래픽 수 MB → KB 단위로 대폭 경량화.
* `client/src/pages/QuotationsPage.tsx` (이전 세션 완료분)
  - 엔드 유저 단 라우팅 최적화. URL 파라미터 `viewId` 매칭 시 `fetchAll` 수행 단계를 제외하고 즉시 해당 레코드만 Fetch되도록 변경.

## 3. 핵심 적용 기술과 맥락 (주의사항)
✅ **의존성 무한 새로고침(루프) 해결**
MonitoringPage에서 수집 진행상태(`PENDING` / `RUNNING`)일때만 백그라운드 재시도(polling)가 필요한데, fetch된 응답 배열(results)이 참조값을 계속 일으키며 useEffect가 무한 파괴/재생성 되던 버그를 `results.some(...)` 부분 상태를 밖으로 빼고 별도 Boolean 트리거로 연계하여 해결했습니다.

✅ **목록과 상세 데이터의 API 분리 (대용량 문제 해결)**
데이터베이스 스키마에서 JSON 포맷의 대형 원문글(`posts` 텍스트 데이터)을 리스트에 전부 담아서 던져주다보니, 데이터가 10건만 넘어도 로딩이 느려지는 원인이었습니다. 이 대형 컬럼들은 개별 클릭했을때(`handleSelectResult`)만 호출되도록 분할했습니다.

✅ **견적서/거래처 서비스 N+1 문제 해결 (이상없음 확인)**
`quotations.ts`에 이미 LEFT JOIN이 들어있고, `AdminPage.tsx`도 `/api/quotations/all-approved-services` 한번의 일괄 호출로 데이터를 구축하는 로직으로 완전히 전환되어 있어 추가 병목 발생이 없음을 확인했습니다.

## 5. 다음 작업시 참고사항
