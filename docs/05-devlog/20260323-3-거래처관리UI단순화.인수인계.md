# 20260323-3 거래처관리UI단순화

## 작업 일시
- 2026-03-23 (오후)

## 작업 요약
거래처 관리 시스템을 전면 단순화. 복잡한 자동 연동/상태 제약 로직을 제거하고, 관리자가 거래처 카드를 중심으로 수동 관리하는 심플한 CRM 구조로 전환.

## 변경 파일 목록

| 파일 | 변경 내용 |
|------|----------|
| `client/src/pages/AdminPage.tsx` | 전면 재작성 (1097줄 → ~500줄). terminated 탭/상태/핸들러 제거, 2x2 버튼 그리드 카드 UI, 소프트 삭제 핸들러 |
| `client/src/components/SubNav.tsx` | '계약 종료' 탭 제거, XCircle import 제거 |
| `server/src/db/schema.ts` | `clients` 테이블에 `deletedAt` 컬럼 추가 |
| `server/src/routes/client.ts` | GET: `deletedAt IS NULL` 필터로 변경, DELETE: 소프트 삭제(deletedAt 설정)로 변경, contractEndedAt 제약 제거 |

## 핵심 변경 내용

### 1. 프론트엔드 — AdminPage.tsx 전면 재작성
- **제거된 것**: `terminatedClients` 상태, `fetchTerminatedClients()`, `handleTerminateClient()`, terminated 탭 UI 전체
- **추가/변경된 것**:
  - 거래처 카드 내 2x2 버튼 그리드: 견적서, 계약서, 사업자등록증, 드라이브
  - 견적서/계약서 버튼 클릭 → 해당 거래처가 선택된 상태로 각 페이지로 `navigate`
  - 하단 "거래처 삭제" 버튼 (hover 시에만 노출, 소프트 삭제)
  - `useNavigate` 추가

### 2. 백엔드 — client.ts
- **GET /api/clients**: `contractEndedAt` 기반 필터 → `deletedAt IS NULL` 기반 필터로 변경
- **DELETE /api/clients/:id**: 계약종료 전제조건 제거, DB 하드삭제 → `deletedAt` 소프트 삭제로 변경. 모니터링 데이터 보존.

### 3. DB 스키마
- `clients` 테이블에 `deleted_at TIMESTAMP` 컬럼 추가 (null=활성, not null=삭제됨)
- Railway DB에 직접 ALTER TABLE로 반영 완료
