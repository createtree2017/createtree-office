## 3. ClientFilter 컴포넌트 설계

### Props
```typescript
interface ClientFilterProps {
    clients: { id: number; name: string }[];     // 병원 목록
    selectedId: number | 'all' | 'unassigned';    // 선택된 필터
    onSelect: (id) => void;                       // 클릭 핸들러
    showUnassigned?: boolean;                     // '미배정' 태그 표시 여부
}
```

### 필터 태그 구성
- **전체** (초록색 활성) — 모든 데이터 표시
- **미배정** (노란색 활성, 회원관리 전용) — `clientId`가 null인 회원
- **각 병원명** (파란색 활성) — 해당 병원 데이터만 표시

## 4. 탭별 필터 적용 현황

| 탭 | 필터 기준 | '미배정' 표시 | 데이터 소스 |
|----|----------|-------------|-----------|
| 회원 관리 | `user.clientId` | ✅ | `clients` (기존 state) |
| 병원 관리 | `client.id` | ❌ | `clients` (기존 state) |
| 견적 관리 | `quotation.clientId` | ❌ | `clients` (기존 state) |
| 계약 관리 | `contract.clientId` | ❌ | `clients` (API 추가 fetch) |
| 계약 종료 | `terminatedClient.id` | ❌ | `terminatedClients` (기존 state) |

## 8. TemplatesPage 인라인 필터 → ClientFilter 통합

### 배경
- 기존 `TemplatesPage.tsx`의 모니터링 탭에 **인라인으로 29줄의 필터 코드**가 있었음
- 거래처관리용 `ClientFilter` 컴포넌트와 기능이 동일하지만 별도 구현이라 DRY 원칙 위반
- 향후 검색 기능 추가 등 유지보수 시 두 곳을 각각 수정해야 하는 문제

### 변경 내용
| 항목 | 변경 |
|------|------|
| `TemplatesPage.tsx` | 인라인 필터 코드(29줄) → `<ClientFilter ... />` (5줄)로 교체 |
| `monClientFilter` 타입 | `number \| null` → `number \| 'all' \| 'unassigned'` (통합 타입) |

### 동작 방식 차이 (props로 분기)
```
// 거래처관리: 전체 clients 목록 전달
<ClientFilter clients={allClients} />

// 상품관리: 데이터에서 추출한 거래처만 전달  
<ClientFilter clients={uniqueMonClients} />
```
→ **컴포넌트는 하나**, 넘겨주는 데이터만 다름

## 10. ClientFilter variant 시스템

### `variant` prop으로 색상 분기
| variant | 용도 | 활성 색상 | 사용처 |
|---------|------|----------|--------|
| `default` | 관리자용 | 초록/파랑 | 거래처관리 5개 탭 |
