# 일일 개발 인수인계

## 기본 정보
- **작업 일자**: 2026-04-20
- **순번**: 4
- **작업 제목**: 견적서 및 계약서 부가세(VAT) 선택 적용 기능 추가

## 핵심 작업 내용
견적서 및 계약서 작성 시 부가세(10%)가 일괄 적용되던 기존 하드코딩 로직을 개선하여, 사용자가 **부가세 적용 여부를 토글할 수 있는 기능**을 구현했습니다. 이를 통해 계산서를 미발행하는 거래 등의 상황에서 유연하게 대응할 수 있게 되었습니다.

### 주요 변경 사항

1. **데이터베이스 스키마 확장 (`server/src/db/schema.ts`)**
   - `quotations` 및 `contracts` 테이블에 `vatIncluded` (Boolean, default: true) 필드 추가.
   - `npx drizzle-kit push --force`를 통해 변경사항 적용 완료 (기존 데이터 하위 호환 유지).

2. **백엔드 API 업데이트**
   - `server/src/routes/quotations.ts`: 견적서 생성(POST) 및 수정(PUT) 시 `vatIncluded` 값을 받아 DB에 저장하도록 구현. 기존 데이터 보호를 위해 미전달 시 `true`를 기본값으로 유지.
   - `server/src/routes/contracts.ts`: 계약 생성 로직에서 원본 견적서의 `vatIncluded` 값을 상속받고, 계약 갱신(renew) 시에도 이전 계약의 상태를 이어받도록 수정.

3. **프론트엔드 UI 및 로직 변경 (`client/src/pages/QuotationsPage.tsx`)**
   - 견적 항목을 추가하는 "칸 만들기" 버튼 옆에 **[부가세(10%) 자동 적용] 체크박스** 토글 UI를 추가.
   - 사용자가 체크박스를 해제하면 즉시 `vatAmount`(부가세액)이 0원으로 재계산되고, 하단의 합계 표시가 **"합계 (VAT 포함)"**에서 **"합계 (VAT 미포함)"**으로 동적으로 변경됨.
   - `QuotationRow` 파싱 시 발생하던 `itemId` 타입 오류 (undefined와 null 미스매치) 해결.
   - 저장(Save) 시 `vatIncluded` 상태값을 서버로 전송하도록 Payload 업데이트.

4. **계약서 조회 연동 (`client/src/pages/ContractsPage.tsx`)**
   - 계약서 상세 보기 모달에서 `detail.vatIncluded` 값에 따라 부가세액(10% 또는 0%)과 안내 텍스트(VAT 포함/미포함)가 정확하게 렌더링되도록 개선.
   - `Contract` 인터페이스에 `vatIncluded` 타입 정의 추가.

5. **템플릿 페이지 타입 오류 수정 (`client/src/pages/TemplatesPage.tsx`)**
   - 기존에 방치되어 있던 `any` 타입 관련 컴파일 에러들을 함께 수정하여 TypeScript 빌드(`npm run build`) 통과 확인 완료.
