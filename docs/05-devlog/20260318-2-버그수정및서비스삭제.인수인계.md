## 2. 작업 1: 견적서 수정 500 오류 수정

### 증상
- 프로덕션에서 기존 견적서 수정 → 저장 시 "견적서 수정 중 오류가 발생했습니다" 500 에러

### 원인
- 클라이언트에서 `validUntil` 필드가 빈 문자열 `''`로 전송됨
- PostgreSQL `date` 타입 컬럼에 빈 문자열 insert 불가 → DB 에러

### 수정 내용

| 파일 | 변경 |
|------|------|
| `server/src/routes/quotations.ts` (line 233) | `validUntil` 빈 문자열 → `null` 변환 |

```diff
- validUntil: validUntil !== undefined ? validUntil : existing.validUntil,
+ validUntil: validUntil !== undefined ? (validUntil || null) : existing.validUntil,
```

> **참고**: POST(생성) 핸들러에는 `validUntil || null` 처리가 이미 있었지만, PUT(수정) 핸들러에만 누락되어 있었음

## 3. 작업 2: Telegram Polling 로컬 개발 비활성화

### 증상
- 로컬 `npm run dev` 실행 시 `❌ Telegram Polling 오류: Request failed with status code 409` 가 무한 반복
- 서버가 오류 폭주로 인해 비정상 종료되는 경우 발생

### 원인
- 프로덕션 Railway 서버와 로컬 서버가 **동일한 Telegram Bot Token**으로 동시 polling
- Telegram API는 같은 토큰으로 동시 polling 시 **409 Conflict** 반환

### 수정 내용

| 파일 | 변경 |
|------|------|
| `server/src/services/notification/telegramService.ts` (line 361~) | `NODE_ENV === 'production'`일 때만 polling 시작 |

```diff
- // 서버 시작 시 자동으로 Polling 시작
- setTimeout(() => { telegramService.startPolling()... }, 2000);
+ // 서버 시작 시 자동으로 Polling 시작 (프로덕션 환경에서만)
+ if (process.env.NODE_ENV === "production") {
+     setTimeout(() => { telegramService.startPolling()... }, 2000);
+ } else {
+     console.log("⚠️ 로컬 개발 환경 — Telegram Polling 비활성화");
+ }
```

## 4. 작업 3: 서비스 삭제 방식 변경

### 변경 사유
- 기존: 휴지통 아이콘 클릭 → `isActive = false` (비활성화) — 사용자에게 혼란
- 변경: 휴지통 아이콘 클릭 → 실제 DB 삭제 (hard delete)

### 수정 내용

| 파일 | 변경 |
|------|------|
| `server/src/routes/services.ts` (DELETE 핸들러) | `db.update → isActive: false` → `db.delete` 실제 삭제 |
| `client/src/pages/ServiceProductsPage.tsx` (line 119) | confirm 메시지: "비활성화" → "삭제" + 경고 문구 |

### 참고: FK 영향
- `serviceTiers`, `serviceItems` → `onDelete: cascade` → 자동 삭제
- `quotationItems.serviceId` → `onDelete: set null` → 기존 견적서에서 serviceId가 null로 변경 (견적서 데이터 자체는 보존)

## 6. 미해결 사항

- **견적서 수정 500 에러**: `validUntil` 수정은 적용했으나, **프로덕션에 배포 전이므로** Railway에서는 아직 오류 발생 가능. 다음 배포 시 반영 필요.
- **견적서 수정 오류 추가 원인 가능성**: 스크린샷에서 프로덕션 500 에러가 계속 발생 중이었음. `validUntil` 외에 다른 원인이 있을 수 있음 → 배포 후 서버 로그 확인 필요.
