# 20260421-2-모니터링PDF생성오류수정.인수인계

## 1. 작업 개요
- **작업일**: 2026-04-21
- **분류**: Quick Fix
- **목적**: Railway 환경에서 모니터링 PDF 생성(및 텔레그램 발송) 시 가상 브라우저가 강제 종료(SIGTRAP)되는 문제 해결
- **요청 사항**: 텔레그램으로 PDF 보고서가 오지 않고 웹사이트에서 PDF 다운로드 시 에러가 발생하는 원인 파악 및 조치

## 2. 원인 분석 및 변경 사항
- **문제 원인**: 
  - 모니터링 보고서를 PDF로 변환할 때 백엔드에서 `Playwright`(가상 브라우저)를 띄워서 처리합니다.
  - 클라우드(Railway) 환경에서 메모리가 부족하거나 리눅스 의존성 패키지가 누락될 경우 브라우저가 켜지자마자 `SIGTRAP` 에러를 내며 강제 종료되는 고질적인 현상이 발생했습니다. (이 때문에 텔레그램에도 텍스트만 가고 PDF가 누락됨)
- **해결 조치**:
  1. `reportGenerator.ts`: 브라우저 실행 시 메모리 사용량을 최소화하고 뻗는 것을 방지하는 안전 옵션(`--disable-dev-shm-usage`, `--disable-gpu`, `--single-process`) 추가
  2. `package.json`: Railway가 서버를 빌드할 때 브라우저 실행에 필요한 리눅스 필수 라이브러리를 강제로 완벽히 설치하도록 `postinstall` 스크립트(`npx playwright install chromium --with-deps`) 추가

## 3. 변경 파일 목록
- `server/src/services/monitoring/reportGenerator.ts` (수정)
  - `chromium.launch` args에 메모리 최적화 옵션 3개 추가
- `server/package.json` (수정)
  - `scripts` 내에 `"postinstall"` 항목 추가

## 4. 동작 확인 상태
- ✅ **코드 패치 완료**: 로컬 환경 코드 수정 완료. (Railway에 배포되면 적용됨)

## 5. 다음 작업 참고사항
- Railway 서버에 이 코드가 Push(배포)되면, 빌드 과정에서 `postinstall` 스크립트가 돌면서 브라우저 환경이 재구성됩니다. 배포 완료 후 PDF 다운로드나 텔레그램 보고서 발송이 정상화되는지 확인이 필요합니다.
