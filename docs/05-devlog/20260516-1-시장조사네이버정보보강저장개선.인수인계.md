## 핵심 변경 내용

- 기존 HIRA 기반 시장조사 선별 로직은 유지했다.
  - HIRA 기본목록 수집
  - HIRA 진료과/전문의 조회
  - HIRA 의료장비 조회
  - 4개 조건 중 3개 이상 분만병원 후보 판정
  - 후보만 네이버 보강
- HIRA 전화번호/홈페이지를 화면용 `phone`, `website`에 우선 저장하지 않고 `rawData.hiraPhone`, `rawData.hiraWebsite`로 보존하도록 변경했다.
- 네이버 보강 저장 기준을 변경했다.
  - 네이버 대표 링크는 `website`에 저장한다.
  - 네이버 플레이스 상세에서 발견한 블로그/인스타그램 링크는 `blog`, `instagram`에 저장한다.
  - 네이버 플레이스 URL은 `https://map.naver.com/p/entry/place/{placeId}` 형식만 `rawData.naverPlaceUrl`에 저장한다.
  - 발견한 전체 링크 목록은 `rawData.naverPlaceLinks`에 보존한다.
- 기존 수집 목록을 HIRA 재수집 없이 네이버 정보만 보강할 수 있는 스크립트를 추가했다.
  - `npm run refresh:market-research-naver --prefix server`
  - 기본은 dry-run이며, 실제 저장은 `-- --write` 또는 `MARKET_RESEARCH_NAVER_REFRESH_WRITE=true`로 실행한다.
  - 기본 대상은 분만병원 후보이며 `MARKET_RESEARCH_NAVER_REFRESH_ONLY_DELIVERY=false`로 전체 항목을 대상으로 바꿀 수 있다.
- 엑셀 다운로드의 `네이버플레이스URL`에서 `rawData.naverLocal.link` fallback을 제거했다.
  - `rawData.manualNaverPlaceUrl || rawData.naverPlaceUrl`만 사용한다.
  - `블로그`, `인스타그램`, `메모` 컬럼을 화면 저장값 기준으로 포함했다.
- 관리자 수동 보정 항목은 재조사 저장 시 연락처/링크/메모와 `rawData.manual*` 값을 우선 보존하도록 했다.

## 운영 참고

- 네이버 플레이스 상세 링크 수집은 네이버 모바일 플레이스 화면의 공개 HTML/스트리밍 데이터를 보조적으로 파싱한다.
- 네이버 화면 구조가 바뀌면 `placeId` 또는 상세 링크 파싱 로직 수정이 필요할 수 있다.
- 기존 전체 DB 갱신 전에는 dry-run과 소량 limit으로 결과를 확인한 뒤 `--write`를 사용한다.
