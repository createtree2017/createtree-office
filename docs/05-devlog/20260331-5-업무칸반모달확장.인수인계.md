## 목적
- 진행 중 파편화되어 많은 업무가 쌓일 시, 칸반 보드의 무한 스크롤 및 성능 저하 방지.
- 각 리스트별 업무를 10개로 제한 노출하고, 그 이상은 전용 확장 뷰(Expanded Modal)를 통해 확인 및 순서 변경(드래그)을 지원하기 위함.

## 변경 파일 목록
- `client/src/components/ExpandedColumnModal.tsx` (신규 파일): 각 칼럼 전체 리스트를 세로로 스크롤하여 조회하고, 직접 `DragDropContext`를 지원하여 순서를 재배치할 수 있게 돕는 대형 모달 UI 구현.
- `client/src/pages/TasksPage.tsx`: 칼럼 렌더링을 10개로 분할(`columnTasks.slice(0, 10)`). 오버플로우 될 경우 숨김 텍스트(+N개) 노출 및 헤더 클릭 이벤트를 통해 `ExpandedColumnModal` 띄우기 속성 주입.

## 핵심 변경 내용
- **칸반 아이템 노출 10개 제한**: 기본 페이지 칸반 로딩 시 성능과 가독성 문제를 고려하여 최대 10개만 바로 렌더링되게 수정.
- **와이드 모달 정렬 연동**: `ExpandedColumnModal` 내부에서 동일한 정렬 로직 및 `/api/tasks/reorder` 통신 구현 완료. 대형 모달에서 업무를 변경하면 최상위 컴포넌트(`TasksPage.tsx`)의 상태 리프레시를 호출(`fetchTasks`)하게 끔 연결.
- **이중 모달(Context-swap) 기법 적용**: 대형 모달에서 업무(카드) 상세 수정 진입 시 모달 오버레이 겹침(Z-index 오류 등) 방지를 위해 `openModal()` Context API를 바로 덮어쓰도록 유도. (대형 뷰 닫힘 -> 상세 뷰 즉시 실행)

## 특이 사항 / 다음 작업
- 프론트엔드와 Context API만으로도 깔끔한 모달 전환(Swap)을 지원.
- 작업 완료로 현재 서버(localhost)에서 실시간으로 드롭 & 드래그, 그리고 상세보기를 확인할 수 있습니다!
