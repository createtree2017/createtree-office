## 1. 개발 범위 개요

본 인수인계서는 **2026년 3월 17일** 하루 동안 개발된 **사업운영관리 시스템**의 전체 내역을 정리한 문서입니다.

| Phase | 기능 | 상태 |
|-------|------|------|
| Phase 1 | 서비스 상품 마스터 | ✅ 완료 |
| Phase 2 | 견적서 시스템 | ✅ 완료 |
| Phase 3 | 계약서 시스템 | ✅ 완료 |

## 2. 전체 데이터 흐름

```
[서비스 상품 마스터]
        │
        ▼
[견적서 생성] ──→ 서비스 선택 → 가격 계산 → 견적서 발행
        │
        ▼ (수락)
[계약서 생성] ──→ 금액/항목 자동 복사 → 계약 내용 작성 → 서명 → 활성화
        │
        ├──→ clients 테이블 계약일정 자동 반영
        ├──→ 거래처 카드에 실행 서비스 상품 표시
        ├──→ 마이페이지에서 담당 회원 조회 가능
        └──→ PDF 다운로드
```

## 3. Phase별 상세

### Phase 1: 서비스 상품 마스터

**목적**: 사내 7개 서비스를 DB 기반 동적 구조로 관리

**DB 스키마 (5개 테이블)**
| 테이블 | 용도 |
|--------|------|
| `services` | 서비스 기본정보 (이름, 과금유형, 활성여부) |
| `service_tiers` | 등급 정보 (ex: 10~20명, 20~30명) |
| `service_items` | 항목 정보 (고정비/변동비) |
| `service_item_prices` | 등급별 항목 가격 매트릭스 |
| `contract_discount_policies` | 계약기간별 할인정책 (6개월 5%, 12개월 10%) |

**API 엔드포인트**: `GET/POST/PUT/DELETE /api/services`, `GET/PUT /api/services/discount-policies`

**프론트엔드**: `ServiceProductsPage.tsx` — 카드 그리드 + 편집 위자드

**시드 데이터**: 7개 서비스 자동 등록 스크립트 (`seedServices.ts`)

---

### Phase 2: 견적서 시스템

**목적**: 거래처별 서비스를 선택하여 견적서 디지털 생성/관리

**DB 스키마 (3개 테이블)**
| 테이블 | 용도 |
|--------|------|
| `quotations` | 견적서 기본정보 (거래처, 금액, 상태) |
| `quotation_items` | 견적 항목 (가격 시점 보존) |
| `quotation_service_configs` | 서비스별 설정 (과금유형, 등급, 이벤트 빈도) |

**핵심 기능**
- 4단계 위자드: 기본정보 → 서비스 선택 → 가격/옵션 → 최종 확인
- 자동 채번: `QT-YYYYMMDD-NNN`
- 자동 계산: 소계 → 할인 → 공급가액 → 부가세(10%) → 합계(VAT포함) → 월 청구액
- 월정액 수량 자동설정 (계약기간 = 수량)
- 가격 시점 보존: 견적 시점 단가 영구 기록

**API 엔드포인트**: `GET/POST/PUT/DELETE /api/quotations`, `PATCH /api/quotations/:id/status`

**프론트엔드**: `QuotationsPage.tsx` — 목록 + 상세뷰 + 4단계 편집 위자드

---

### Phase 3: 계약서 시스템

**목적**: 수락된 견적서를 계약서로 변환하고 계약 상태를 관리

**DB 스키마 (1개 테이블)**
| 테이블 | 용도 |
|--------|------|
| `contracts` | 계약서 정보 (상태, 금액, 공통조항, 특별조항) |

**핵심 기능**
- 견적서 → 계약서 원클릭 변환 (`POST /api/contracts/from-quotation/:id`)
- 계약 상태 흐름: `draft → signed → active → expired/terminated`
- clients 자동 연동: 활성화 시 계약일정 자동 업데이트
- 계약 해지 안전 처리: 다른 활성 계약 존재 시 거래처 해지 방지
- 계약 갱신: 기존 계약 만료 + 신규 계약 생성 원자적 처리
- 계약 내용: 공통 계약 내용 + 업체별 특별 조항 분리
- 자동 채번: `CT-YYYYMMDD-NNN`
- 수정 기능: draft/signed 상태에서 전체 수정 가능

**API 엔드포인트**: `GET/PUT /api/contracts`, `PATCH /api/contracts/:id/status`, `POST /api/contracts/:id/renew`

**프론트엔드**: `ContractsPage.tsx` — 목록 + 상세뷰 + 수정/갱신 폼

**거래처 관리 연동 (AdminPage)**
- 거래처 카드에 `📋 계약서 정보됨` 배지 표시
- 활성 계약의 서비스 상품 표시 (`GET /api/contracts/client/:clientId/services`)
- 견적서 수락 취소 기능 추가

---

### Phase 4: PDF 다운로드 + 마이페이지

**목적**: 문서 PDF 출력 + 담당 회원 자기 거래처 현황 조회

**PDF 다운로드**
- 라이브러리: `html2pdf.js` (클라이언트 사이드)
- 견적서: `📥 PDF` 버튼 → `QT-20260317-001.pdf`
- 계약서: `📥 PDF` 버튼 → `CT-20260317-002.pdf`
- 옵션: A4 세로, 2x 고화질, 여백 10mm

**마이페이지 계약현황**
- API: `GET /api/contracts/my/status` (JWT 인증, 모든 권한)
- 회원의 `clientId`로 해당 거래처의 견적서/계약서 조회
- UI 구조: 활성계약 요약 카드 + 견적서/계약서 펼침/접힘 리스트

```
마이페이지
├── 👤 회원정보
├── 📋 계약 & 견적 현황 ← 신규
│   ├── 🟢 활성 계약 요약
│   ├── [견적서 N건] 토글
│   └── [계약서 N건] 토글
├── 🔒 비밀번호 변경
└── 🚪 로그아웃
```

## 7. 주의사항 및 알려진 사항

### Express 라우트 순서
- `/api/services/discount-policies`는 `/api/services/:id`보다 **반드시 앞에** 배치
- `/api/contracts/my/status`는 `/api/contracts/:id`보다 **반드시 앞에** 배치

### 가격 단위
- 모든 금액은 **만원 단위**로 저장 및 표시
- 부가세(VAT)는 화면 표시용으로만 계산 (DB에 별도 저장하지 않음)
- VAT = 공급가액 × 10%

### 계약 상태 변경 시 자동 동작
| 상태 변경 | 자동 동작 |
|-----------|----------|
| → active | clients.contractStartDate, contractEndDate 업데이트, contractFileName에 계약번호 저장 |
| → terminated | 다른 활성 계약이 없을 때만 clients.contractEndedAt 설정 |
| 갱신 실행 | 기존 계약 expired + 신규 계약 active + clients 정보 업데이트 (원자적) |

### 마이페이지 표시 조건
- 사용자에게 `clientId`가 연결되어 있어야 계약현황 섹션이 표시됨
- ADMIN이 관리 페이지에서 사용자에게 거래처를 할당해야 동작
