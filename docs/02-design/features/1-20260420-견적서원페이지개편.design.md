# 설계서: 견적서 작성 One-Page 통합 UI 개편

## 1. 개요
* **작성일**: 2026-04-20
* **관련 기능**: 견적서 작성 (QuotationsPage.tsx)
* **목적**: 기존 4단계 위자드(Wizard) 방식의 견적서 작성 UI를 제거하고, 엑셀 및 ERP 스타일의 단일 페이지(One-Page) 테이블 UI로 전면 개편하여 사용자의 작성 편의성과 직관성을 극대화합니다.

## 2. 데이터베이스 스키마 변경 사항
테이블 UI에서 "비고(신규)" 컬럼을 추가하기 위해 기존 `quotation_items` 테이블 구조에 대한 확장이 필요합니다.

### 2.1. 추가/수정될 테이블
* **테이블명**: `quotation_items`
* **추가할 컬럼**:
  * `remark` (text): 개별 서비스 항목에 대한 비고/메모 (선택)
  * `is_custom` (boolean, default: false): "직접 입력" 또는 "할인"으로 추가된 커스텀 항목인지 식별하는 플래그 (선택 사항이지만 데이터 무결성을 위해 권장)

## 3. 프론트엔드 UI/UX 설계

### 3.1. 화면 구성 (단일 뷰)
`+ 견적서 작성` 클릭 시 기존의 Step 1~3 화면은 나타나지 않으며, 아래와 같은 구조의 단일 폼 화면이 표시됩니다.

#### [상단] 기본 정보 (헤더 영역)
* **거래처**: Select (드롭다운)
* **계약 기간**: Select (드롭다운, 단건/3개월/6개월/12개월 등)
* **견적서 제목**: Text Input (예: ○○병원 서비스 견적서)
* **전체 비고**: Textarea (선택)

#### [중단] 서비스 항목 테이블 (메인 영역)
* **테이블 헤더**: 
  `서비스(선택)` | `항목(자동/입력)` | `단가(자동/입력)` | `수량(입력)` | `금액(자동/수동)` | `비고(신규)`
* **테이블 바디 (행/Row)**:
  1. **서비스 선택 드롭다운**: DB에 등록된 서비스 목록 (기존 Service Master 연동)
     * 맨 하단에 특수 옵션으로 `[+ 직접 입력]`, `[- 할인]` 메뉴 고정 배치.
  2. **항목명**: 서비스 선택 시 자동 입력. (직접 입력 시 Text Input으로 전환)
  3. **단가**: 서비스 및 등급 선택 시 자동 산출. (직접 입력 시 Number Input으로 전환)
  4. **수량**: 기본 1 (월정액의 경우 계약 기간으로 자동 세팅), 수정 가능.
  5. **금액**: `단가 * 수량`으로 자동 계산. (할인 선택 시 음수 금액 입력 가능)
  6. **비고**: 텍스트 입력창 (할인 사유나 특이사항 기재).
  7. **삭제 버튼 (X)**: 해당 행 삭제.
* **행 추가 버튼**: 
  * 테이블 맨 아래에 `+ 칸 만들기 (서비스 추가)` 버튼 배치.

#### [하단] 결제/합계 영역
* 각 행의 `금액` 값을 실시간 감지하여 자동 산출:
  * **소계**: 모든 행 금액의 단순 합.
  * **공급가액**: 소계에서 할인을 적용한 최종 금액 (할인 행이 추가되었으므로 소계와 동일하게 처리해도 무방함).
  * **부가세 (10%)**: 공급가액 * 0.1
  * **합계 (VAT 포함)**: 최종 결제 금액.

### 3.2. 상태 관리 (React State)
* 기존 `QuotationsPage.tsx`의 `step`, `selectedServices`, `form` 등 복잡한 상태를 다음과 같이 단일화합니다.
```typescript
interface QuotationFormState {
  clientId: number;
  title: string;
  contractMonths: number;
  notes: string;
}

interface QuotationRowState {
  id: string; // 임시 식별자 (Date.now() 등)
  serviceId: number | 'custom' | 'discount';
  serviceName: string;
  itemName: string;
  unitPrice: number;
  quantity: number;
  amount: number;
  remark: string;
  isCustom: boolean;
}
```
* `rows` 상태 배열을 기반으로 테이블을 렌더링하고 `map` 함수를 사용하여 각 행의 값 변동(onChange)을 처리합니다.

## 4. API 변경 사항
* `POST /api/quotations` 및 `PUT /api/quotations/:id` 엔드포인트 수정:
  * Request Body의 `items` 배열에 새로 추가된 `remark`, `is_custom` 필드를 매핑하여 DB에 저장하도록 처리.
  * 프론트엔드에서 할인율을 계산하여 던지던 로직을, `rows` 배열의 "할인" 행으로 일원화하여 저장하도록 백엔드 로직 간소화.
