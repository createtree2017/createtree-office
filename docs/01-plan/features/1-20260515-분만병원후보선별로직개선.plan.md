# 분만병원 후보 선별 로직 개선 Plan

## 목적

시장조사 원본은 HIRA 산부인과 진료과목 보유기관 전체를 보존하되, 실제 영업 우선순위가 높은 분만 가능 병원/의원을 낮은 비용과 높은 신뢰도로 선별한다.

현재 시장조사 결과에는 요양병원, 내과/가정의학과 중심 의원 등 산부인과 진료과목만 보유한 기관도 포함된다. 이는 원본 수집 관점에서는 정상이나, 영업 후보 선별에는 별도 필터와 상세조사 기준이 필요하다.

## 핵심 원칙

- 원본 수집과 영업 후보 선별을 분리한다.
- HIRA를 1차 공식 원천으로 사용한다.
- 네이버는 국내 병원 검색 현실에 맞게 산부인과 카테고리 필터로만 사용한다.
- 구글은 기본 수집 흐름에서 제외한다.
- 기관은 자동 삭제하지 않고 상태와 점수로 분류한다.
- 비용보다 호출 한도 관리가 핵심이다.

## 수집 원천 역할

### HIRA

주 원천이다.

- 산부인과 진료과목 보유기관 전체 조회
- 병원명
- 기관종별
- 주소
- 전화번호
- 홈페이지
- 좌표
- 전체 의사 수
- HIRA 기관 ID `ykiho`
- 진료과목별 의사/전문의 수
- 소아청소년과 보유 여부
- 특수진료장비
- 인큐베이터 보유 여부
- 분만감시기 보유 여부

### 네이버

국내 영업 기준의 카테고리 필터로만 사용한다.

- 네이버 등록명
- 네이버 카테고리
- 네이버 도로명/지번 주소
- 네이버 좌표
- 네이버 링크

상세조사 후보 기준:

- 네이버 `category`가 `병원,의원>산부인과`
- 또는 기관명에 아래 키워드 포함
  - `여성병원`
  - `산부인과병원`
  - `산부인과`
  - `미즈`
  - `우먼`
  - `모아`
  - `맘`
  - `아이`

제외하는 예외 기준:

- HIRA 기관종별이 병원/종합병원/상급종합이라는 이유만으로 상세조사 후보에 포함하지 않는다.

### 구글

기본 흐름에서는 제외한다.

- 국내 병원 영업 기준에서는 네이버보다 효율이 낮다.
- 분만병원 후보 판정에 필요한 산부인과 전문의 수, 소아청소년과 여부, 인큐베이터 여부를 제공하지 않는다.
- Places API 비용 발생 가능성이 있다.
- 추후 예외적인 수동 검증 보조 수단으로만 검토한다.

## 목표 로직

1. HIRA 기본목록으로 산부인과 진료과목 보유기관 전체 수집
   - 원본은 모두 저장한다.
   - 병원명, 주소, 전화번호, 홈페이지, 기관종별, 전체 의사 수, 좌표, `ykiho`를 저장한다.

2. 네이버 지역검색으로 산부인과 카테고리 필터링
   - HIRA 병원명 + 주소를 기준으로 네이버 지역검색을 수행한다.
   - 네이버 카테고리가 `병원,의원>산부인과`이면 상세조사 후보로 표시한다.
   - 네이버 카테고리가 맞지 않아도 기관명 키워드 조건에 해당하면 상세조사 후보로 표시한다.
   - 통과하지 못한 기관도 삭제하지 않고 `needs_review` 또는 낮은 우선순위로 남긴다.

3. 상세조사 후보만 HIRA 진료과목 상세 조회
   - 산부인과 의사/전문의 수 저장
   - 소아청소년과 존재 여부 저장

4. 상세조사 후보만 HIRA 의료장비 상세 조회
   - 인큐베이터 수 저장
   - 분만감시기 수 저장

5. 분만병원 후보 점수 계산
   - 산부인과 의사/전문의 3명 이상: 1점
   - 소아청소년과 있음: 1점
   - 인큐베이터 있음: 1점
   - 분만감시기 있음: 1점

6. 후보 등급 분류
   - 4점: 강력 분만 후보
   - 3점: 분만 후보
   - 2점: 검토 후보
   - 0~1점: 낮은 우선순위

7. 영업선택은 사용자가 최종 결정
   - 자동 점수는 후보 추천까지만 담당한다.
   - `sales_leads` 생성은 기존처럼 사용자의 선택 액션으로 처리한다.

## 비용 및 호출 한도

금전 비용은 사실상 0원으로 예상한다. 관리 대상은 호출 한도다.

### 예상 호출량

5,307건 기준:

- HIRA 기본목록: 약 54회
- 네이버 지역검색: 약 5,307회
- HIRA 진료과목 상세: 상세조사 후보 수만큼
- HIRA 의료장비 상세: 상세조사 후보 수만큼

예상 상세조사 후보가 1,500건이면:

- HIRA 상세 호출: 약 3,000회
- 전체 HIRA 호출: 약 3,054회
- 네이버 호출: 약 5,307회

### 한도 기준

- HIRA 개발계정: 10,000회/day 기준으로 관리
- 네이버 검색 API: 25,000회/day 기준으로 관리

전체 5,307건에 HIRA 상세 2종을 모두 실행하면 10,614회로 HIRA 개발계정 한도를 초과할 수 있다. 따라서 네이버 카테고리와 기관명 키워드로 상세조사 후보를 줄인 뒤 HIRA 상세를 호출한다.

## 화면 변경 방향

- `산부인과 보유기관`은 전체 원본 필터로 유지한다.
- `분만병원` 필터는 기존 `businessType === delivery_hospital` 중심이 아니라 `deliveryCandidateScore >= 3` 또는 `deliveryCandidateGrade` 기준으로 변경한다.
- 표에 아래 항목을 표시한다.
  - 산부인과 의사 수
  - 소아청소년과 여부
  - 인큐베이터 수
  - 분만감시기 수
  - 분만 후보 점수/등급
  - 네이버 카테고리 매칭 여부

## 성공 기준

- HIRA 산부인과 진료과목 보유기관 전체가 원본으로 보존된다.
- 네이버 카테고리 `병원,의원>산부인과` 기준으로 상세조사 후보가 분리된다.
- 기관명 키워드 예외가 적용된다.
- HIRA 상세정보로 산부인과 의사 수, 소아청소년과 여부, 인큐베이터, 분만감시기를 저장한다.
- 4개 조건 중 3개 이상 충족한 기관이 분만병원 후보로 필터링된다.
- 요양병원/타과 중심 기관은 원본에는 남되 영업 우선순위에서 낮게 분류된다.
- 구글 API를 호출하지 않아 Places 비용이 발생하지 않는다.
- `npm run build --prefix server`와 `npm run build --prefix client`가 통과한다.

## 구현 순서

2. HIRA 상세 진료과목 조회 함수 추가
3. HIRA 상세 의료장비 조회 함수 추가
4. 상세조사 후보 판정 함수 추가
5. 분만 후보 점수 계산 함수 추가
6. Google Places 보강 기본 비활성화 또는 제거
7. API 결과와 DB 저장 로직 연결
8. 화면 필터와 표 컬럼 조정
9. 소량 샘플 검증
10. 전체 실행 전 호출량 제한값 검증

## 리스크

- 네이버 지역검색 결과 매칭 오류가 있을 수 있다.
- 네이버 카테고리 누락 기관이 있을 수 있다.
- HIRA 상세 API endpoint별 응답 필드가 기관마다 비어 있을 수 있다.
- HIRA 개발계정 호출 한도를 넘을 수 있다.
- DB 컬럼 추가가 필요하면 migration과 운영 DB 반영 절차가 필요하다.

## 운영 참고

- 원본 보존과 후보 선별을 혼동하지 않는다.
- 자동 후보 점수는 영업 선택의 보조 기준이다.
- 최종 영업대상 저장은 기존 영업선택 액션으로 처리한다.

## 2026-05-15 구현 업데이트

- HIRA 상세 API는 승인 화면 기준의 `MadmDtlInfoService2.7` endpoint를 사용한다.
  - 전문과목별 전문의 수: `getSpcSbjtSdrInfo2.7`
  - 의료장비: `getMedOftInfo2.7`
- 네이버 지역검색은 429 방지를 위해 호출 간격과 재시도 후퇴 대기를 적용한다.
  - `MARKET_RESEARCH_NAVER_DELAY_MS` 기본 350
  - `MARKET_RESEARCH_NAVER_RETRY_DELAY_MS` 기본 2000
  - `MARKET_RESEARCH_NAVER_MAX_RETRIES` 기본 3
- 네이버 검색어는 긴 HIRA 주소 전체 대신 `지역+상호`, `상호+짧은주소`, `상호` 순서로 fallback한다.
- 전체 시장조사 없이 프로덕션 샘플만 검증하는 스크립트를 추가했다.
  - `server/scripts/test-market-research-production-sample.ts`
  - 고은빛 샘플 기준 네이버 카테고리, HIRA 상세 전문의 수, 인큐베이터, 분만감시기, 분만 후보 점수를 검증한다.
- DB 스키마 변경은 없다.
- 검증 명령:
  - `npm run build --prefix server`
  - `npm run build --prefix client`
  - `npm run lint:market-research --prefix client`
  - `npx tsx scripts/test-market-research-production-sample.ts` (`server/` 기준)
