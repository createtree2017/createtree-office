# 계약서 시스템 — Plan

## 목적
견적서(수락)를 계약서로 변환하고, 계약 상태를 관리하는 시스템.
기존 `clients` 테이블의 계약 관련 필드와 연동.

## 핵심 설계

### DB 스키마 (1개 테이블 + 1개 enum 추가)

**contract_status** enum: draft → signed → active → expired → terminated

**contracts** (계약서)
- id, contractNumber (자동 채번 CT-YYYYMMDD-NNN)
- quotationId (→ quotations FK), clientId (→ clients FK)
- title, contractMonths, startDate, endDate
- subtotal, discountAmount, totalAmount, monthlyAmount
- notes, status, signedAt, createdBy (→ users FK)
- timestamps

### 핵심 로직
1. **견적서 → 계약서 원클릭 변환** (견적서 status=accepted → 계약서 생성)
2. **계약 활성화 시** clients.contractStartDate/EndDate 자동 업데이트
3. 계약 항목은 quotation_items를 참조 (별도 복사 X — 원본 견적서 보존)

### API (server/src/routes/contracts.ts)
| Method | Endpoint | 설명 |
|--------|----------|------|
| GET | /api/contracts | 계약 목록 |
| GET | /api/contracts/:id | 계약 상세 |
| POST | /api/contracts/from-quotation/:quotationId | 견적서→계약서 변환 |
| PUT | /api/contracts/:id | 계약 수정 |
| PUT | /api/contracts/:id/status | 상태 변경 (활성화 시 clients 업데이트) |

### 프론트엔드 (client/src/pages/ContractsPage.tsx)
- 목록: 계약 테이블 (번호, 거래처, 금액, 기간, 상태)
- 상세: 계약서 뷰 (견적서 항목 포함)
- 견적서 상세에서 "계약서 생성" 버튼 추가

## 검증 계획
1. DB 마이그레이션 확인
2. 견적서 → 계약서 변환 테스트
3. 계약 활성화 → clients 테이블 업데이트 확인
